## 1. Project Overview

Zecpath AI is an AI-powered job portal and automated hiring platform.
It supports the recruitment lifecycle through resume processing, candidate analysis, ATS scoring, screening, interview evaluation, decision support and recruitment workflow automation.

The platform organizes AI capabilities into specialized components that communicate through defined application and API workflows.

## 2. Project Objectives

- Automate repetitive recruitment activities.
- Extract structured information from candidate resumes.
- Match candidate profiles against job requirements.
- Support consistent candidate screening.
- Assist HR and technical interview workflows.
- Generate explainable evaluation results.
- Support recruiter decision-making.
- Improve recruitment processing efficiency.

## 4. System Architecture

The platform follows a modular architecture in which specialized AI components perform individual recruitment tasks.

Main layers:

1. Presentation Layer: Candidate and recruiter interfaces.
2. Backend Layer: Request handling, authentication and workflow coordination.
3. AI Processing Layer: Resume parsing, matching, scoring, screening and interview evaluation.
4. Data Layer: Candidate profiles, job profiles, results and supporting records.
5. Monitoring Layer: Logs, metrics, errors and audit information.

The existing ATS pipeline coordinates resume extraction, candidate analysis, semantic matching, scoring and ranking.

### 5.7 ATS Scoring Engine

Implementation reference: src/ats_scoring/engine.py

The documented ATS scoring engine uses four components:
- Skill Match.
- Experience Relevance.
- Education Alignment.
- Semantic Similarity.

Role-based weights:

| Role | Skills | Experience | Education | Semantic |
|---|---:|---:|---:|---:|
| Data Analyst | 40% | 25% | 15% | 20% |
| Software Developer | 45% | 30% | 10% | 15% |
| ML Engineer | 45% | 30% | 10% | 15% |
| Business Analyst | 45% | 30% | 10% | 15% |
| Default | 40% | 25% | 15% | 20% |

Formula:

Weighted Score = Sum of (Normalized Component Score x Component Weight)

The normalized result is converted to a 0-100 ATS score.

Missing-data handling:
- Missing or invalid values are normalized safely.
- Missing components are recorded.
- Missing components are excluded from active weighting.
- Remaining weights are normalized.
- If all components are missing, the score becomes 0.

ATS score classifications:

| Score | Classification |
|---|---|
| 85-100 | Excellent Match |
| 70-84.99 | Strong Match |
| 50-69.99 | Moderate Match |
| 40-49.99 | Weak Match |
| Below 40 | Low Match |

### 5.8 Candidate Ranking

Implementation reference: src/candidate_ranking/engine.py

The ranking engine consumes ATS scores generated by the scoring engine.
It sorts candidates in descending order of ATS score.
It does not independently recalculate ATS scores.

Decision thresholds:

| ATS Score | Decision |
|---|---|
| 70 or above | SHORTLIST |
| 50 to 69.99 | REVIEW |
| Below 50 | AUTO-REJECT |

### 5.9 Eligibility Decision Engine

Purpose: Evaluate whether a candidate satisfies role-specific eligibility conditions.

Documented eligibility factors include:
- ATS score.
- Mandatory skills.
- Experience requirements.
- Location.
- Availability.
- Role-specific thresholds.

Possible outcomes:
- ELIGIBLE.
- REVIEW.
- REJECTED.

This stage consumes existing candidate information and ATS results rather than replacing the scoring engine.

### 5.10 Screening AI

### 5.11 Interview AI

| Field | Description |
|---|---|
| job_id | Unique job identifier |

| preferred_skills | Additional skills |
| experience | Experience requirement |
| education | Education requirement |

### Skill Object

Represents an individual candidate or job-related skill.

Suggested fields: skill_name, skill_category and relevance.

### Experience Object

Represents an individual experience record.

Suggested fields: designation, company, duration and responsibilities.

### AI Result Metadata

Important metadata fields:
- candidate_id.
- job_id.
- model_version.
- timestamp.

These identifiers support traceability and result versioning.

## 10. Testing

The project uses pytest for automated testing.

Run the test suite from the project root:

```powershell
python -m pytest -v
```

Run a targeted test by specifying its test path:

```powershell
python -m pytest -v path/to/test_file.py
```

Always investigate failures before changing existing scoring, ranking or pipeline behavior.
