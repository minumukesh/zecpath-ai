# Zecpath AI - System Architecture Documentation

## 1. Architecture Overview

Zecpath AI organizes recruitment functionality into modular application and AI processing components.

## 3. Main Components

| Component | Responsibility |
|---|---|
| Resume Extraction | Extract resume content |
| Skill Extraction | Identify candidate skills |
| Experience Parser | Structure experience |
| Education Parser | Structure qualifications |
| Semantic Matching | Compare candidate and job content |
| ATS Scoring | Calculate weighted matching score |
| Candidate Ranking | Sort candidates by ATS score |
| Eligibility Engine | Apply role-specific eligibility rules |
| Screening AI | Support early candidate screening |
| Interview AI | Support interview evaluation |
| Decision AI | Provide decision support |

## 5. Architecture Principles

- Keep services modular.
- Reuse existing ATS components.
- Keep scoring and ranking responsibilities separate.
- Use structured data between processing stages.
- Validate API inputs and outputs.
- Maintain traceability of AI results.
- Avoid duplicate scoring implementations.

## 6. ATS Scoring and Ranking Separation

```text
Candidate Data
      |
      v
ATS Scoring Engine
      |
      v
Normalized Component Scores
      |
      v
Final ATS Score
      |
      v
Candidate Ranking Engine
      |
      v
SHORTLIST / REVIEW / AUTO-REJECT
```

The ranking engine consumes the score generated by the scoring engine. It does not calculate a second ATS score.

## 7. Integration and Storage

Backend services coordinate requests between the frontend, AI components and data storage.

The Day 59 API endpoints are proposed integration contracts. Verify actual routes in the source code before treating them as implemented.

## 8. Architecture Status

This document combines documented ATS architecture and proposed integration designs. It is not a claim that every proposed service has been deployed.
