# Day 50: Task Evaluation Logic

## Task categories

| Task type | Evaluation focus |
|---|---|
| Coding | Algorithm correctness, edge cases, complexity |
| Debugging | Defect identification, root cause, corrected behavior |
| File-based | File processing, validation, output correctness |
| System design | Architecture, scalability, reliability, trade-offs |

## Correctness

Correctness is calculated using the proportion of passed test cases.

## Efficiency

Efficiency is supplied by the evaluator using runtime and resource
measurements. The demo uses synthetic scores.

## Code quality

Code quality is assessed using a documented rubric covering readability,
maintainability, modularity, and appropriate error handling.

## Problem-solving

Problem-solving is assessed using a rubric covering decomposition,
reasoning, edge cases, and explanation of the approach.

## Time-based scoring

When time taken exceeds the configured limit, a capped penalty is applied.

## Explainability

The report exposes each metric, its weight, its contribution, the time
penalty, and the final score.
